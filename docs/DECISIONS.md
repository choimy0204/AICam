# 결정 기록

명세(SPEC.md)에서 정해지지 않았거나 서로 충돌한 부분을 어떻게 처리했는지 남긴다.

## 공통
- 패키지/applicationId: `com.aiguidecamera`
- 빌드: AGP 8.12.3, Kotlin 2.2.10, Gradle 8.14.5, compileSdk/targetSdk 36, minSdk 26. JDK는 Android Studio JBR.
- 9절(갤러리·사후 편집)은 **Phase 2.5**로 둔다. 필터 렌더러가 있어야 하므로 Phase 2 뒤.
- 헤드룸 임계값: 3절(3%/20%)과 10절(5%/15%)이 충돌 → **10절 값** 사용.

## Phase 1
- 프리뷰·촬영 모두 4:3. 프리뷰 영역은 3:4 박스, 렌더러는 center-crop.
- 화면은 세로 고정. 폰을 가로로 잡으면 `OrientationEventListener`로 촬영본 방향만 맞춘다.
- 프리뷰 회전은 CameraX `TransformationInfo.rotationDegrees`를 정점 행렬로 적용한다
  (SurfaceTexture 변환 행렬에는 센서 회전이 들어 있지 않다).
- 촬영: `ImageCapture` 메모리 콜백 → `toBitmap()` → `rotationDegrees`만큼 회전 → `OffscreenFilterRenderer` → JPEG(품질 95).
- 원본 저장본도 똑바로 세운 비트맵을 JPEG로 다시 인코딩해 저장한다 (EXIF 회전에 의존하지 않음 → 사후 편집이 단순해짐).
- `OffscreenFilterRenderer`는 Application이 하나만 들고 프로세스 수명 동안 유지한다.
- API 26~28은 `WRITE_EXTERNAL_STORAGE`로 Pictures/AIGuideCamera에 직접 쓰고 MediaStore에 등록한다.
- PhotoRecord(Room)는 Phase 1부터 기록한다. 필터가 없으므로 `filterId = "none"`.
- 셔터음: `MediaActionSound`.

## Phase 2
- LUT: 512x512 PNG(8x8 타일, 64³)를 `tools/generate_luts.py`(표준 라이브러리만)로 생성해 `assets/luts/`에 커밋한다.
  앱은 PNG를 디코딩해 `GL_TEXTURE_3D`(RGB8)로 올리고 하드웨어 3선형 보간으로 샘플링한다. 디코딩 결과는 두 GL 컨텍스트가 공유.
- 페이드는 LUT에만 굽는다 (셰이더 파라미터는 강도·그레인·비네팅만). 강도 = 원본과 LUT 결과의 mix, 그레인·비네팅에도 강도를 곱한다.
- 셰이더 한 패스: 피부 보정 → LUT mix → 비네팅 → 그레인. 프리뷰(OES)와 저장(2D)은 `sampleSource()` 헤더만 다르고 본문 문자열이 같다.
  정밀도는 highp (저장본 그라데이션 밴딩 방지).
- 비네팅·그레인·얼굴 마스크는 "똑바로 선 사진 기준 좌표"로 계산한다. 프리뷰는 center-crop·거울 반전을 역산한 변환을 넘긴다
  → 화면과 저장본에서 같은 위치에 같은 효과. 그레인 셀 크기·블러 반경도 해상도 대비 비율이라 프리뷰와 저장본 느낌이 같다.
- "원본" 필터(id `none`)를 목록 맨 앞에 둔다 (10종 + 원본).
- 기본값: 인물 `clear_skin`, 음식 `food_warm`, 강도 0.8, 피부 보정 0.4. 모드별 마지막 필터·강도는 SharedPreferences에 기억.
- 피부 보정은 인물 모드에서만 (음식 모드는 0). 저장 시 고해상도 원본을 1280px로 줄여 ML Kit Face Detection을 한 번 돌려 얼굴 박스를 얻는다.
  검출 실패 시 피부 보정 없이 저장. 프리뷰 피부 보정은 Phase 3의 실시간 얼굴 박스가 들어오면 동작한다 (`GLRenderer.setFaceBoxes`).
- 필터 썸네일: 색 띠 견본 이미지를 `OffscreenFilterRenderer`로 렌더링 (결과물과 같은 경로).
- 강도·피부 보정 슬라이더는 프리뷰 위 반투명 패널. 선택된 필터 썸네일을 다시 탭하면 열고 닫는다 (화면 높이 확보).

## Phase 2.5
- "원본도 함께 저장" 설정(`AppSettings`, 기본 OFF)과 최소 설정 화면을 Phase 6보다 앞당겨 만들었다.
  원본이 있어야 사후 편집을 실기기에서 확인할 수 있기 때문. 카메라 화면 오른쪽 아래 톱니바퀴로 들어간다.
- 화면 이동: navigation-compose. 카메라 → (썸네일) 갤러리 → 상세 → 필터 변경. 편집 저장 후에는 갤러리로 돌아간다.
- 편집 미리보기는 원본을 긴 변 1600px 이상이 되도록 inSampleSize로 줄여 읽고, 값이 바뀔 때마다 `OffscreenFilterRenderer`로
  다시 그린다(collectLatest). 저장은 원본 전체 해상도로 같은 렌더러를 한 번 더 돌린다.
- 얼굴 박스는 축소 원본에서 한 번만 검출해(0~1 좌표라 해상도 무관) 미리보기와 저장에 같이 쓴다.
- 편집 저장 파일명은 저장 시각 기준 `IMG_yyyyMMdd_HHmmss.jpg`, 새 PhotoRecord는 원본 Uri·모드를 그대로 이어받는다.
- 편집 화면에서는 모드와 무관하게 피부 보정 슬라이더를 보여준다(음식 사진이면 얼굴이 없어 효과 없음).

## Phase 3 — 분석 파이프라인 + 디버그 오버레이

- **ImageAnalysis 640x480(4:3), KEEP_ONLY_LATEST, 10fps 스로틀**: 포즈·얼굴 동시 처리에 충분하고 저사양에서도 밀리지 않는 크기. 프리뷰·촬영과 같은 4:3이라 0~1 좌표를 그대로 공유한다.
- **좌표계 통일**: 모든 분석 좌표는 "똑바로 선 사진 기준 0~1, 거울 반전 없음". 저장본·오프스크린 피부 보정과 같은 좌표라 얼굴 박스를 프리뷰 셰이더에 그대로 넘긴다. 거울 반전은 화면에 그릴 때만(디버그 오버레이) 적용.
- **ML Kit Pose(base, STREAM_MODE) + Face(FAST, 분류 ON)를 병렬 실행**, `Tasks.whenAllComplete` 뒤 같은 분석 스레드에서 밝기 계산 후 ImageProxy를 닫는다. 음식 모드는 포즈·얼굴을 건너뛴다.
- **밝기·색은 YUV 직접 샘플링(8px 격자)**: Bitmap 변환 없이 할당 0. 얼굴 밝기는 버퍼 좌표를 회전 반영해 얼굴 박스와 비교.
- **센서**: 회전 벡터 → pitch = asin(R[8]) (0 = 정면, 90 = 탑뷰), roll = atan2(R[6], R[7])을 가장 가까운 90° 기준 ±45°로 정규화(가로 촬영 대응). 자이로는 분석 간격 사이 최댓값을 쓴다(순간 흔들림 놓치지 않게). 화면이 보일 때만 등록.
- **poseMotion**: 두 프레임 모두 신뢰도 ≥ 0.5인 관절의 평균 이동 거리. 자동 촬영의 "피사체 정지" 판단용.
- **디버그 오버레이**: 프리뷰 좌상단 "DBG" 토글. 관절 점(초록 = 신뢰, 빨강 = 낮음), 얼굴 박스(노랑), roll/pitch/gyro/밝기/RGB/눈 뜸/yaw 수치. 임계값 튜닝 용도.

## Phase 4 — 규칙 엔진 + 조언 UI

- **FaceInfo.box를 RectF → NormRect(순수 Kotlin)로 교체**: android.graphics.RectF는 JVM 단위 테스트에서 동작하지 않아(스텁) 규칙 테스트가 불가능. 렌더러로 넘길 때만 RectF로 변환한다.
- **샷 종류 판별(ShotClassifier)**: 신뢰도 ≥ 0.5 관절 기준, 발목 → 전신 / 엉덩이 → 상반신 / 어깨 → 클로즈업. 헤드룸 기준표는 샷별로 두라고 했지만 SPEC에 전신 값만 있어 일단 모든 샷에 같은 값(0.05~0.15)을 쓴다. 실기기 튜닝 때 샷별로 나눈다.
- **정수리 추정**: 얼굴 박스 top − 박스 높이 × 0.25(머리카락). 얼굴이 없으면 코 − (어깨선−코) × 0.65.
- **CameraHeightRule 휴리스틱**: 피치 > 10° 또는 (전신일 때) (코→엉덩이)/(엉덩이→발목) > 1.0이면 내려다본 것으로 판단.
- **HorizonRule은 |피치| > 60°면 건너뜀**: 탑뷰에서는 중력이 화면과 수직이라 롤 값이 의미 없다. 롤 음수(시계 방향으로 기움) → ROTATE_LEFT.
- **수평선은 정규화 전 롤(deviceRollDeg)로 회전**: 화면이 세로 고정이라 가로로 잡아도 실제 수평과 맞게 그린다. 판정·초록 표시는 정규화된 롤로.
- **IssueStabilizer**: 규칙별 연속 감지/소실 카운터. "좋아요"도 문제 없는 프레임이 5연속일 때만 표시(시작 직후·전환 직후 초록 깜빡임 방지). 그 사이는 Pending(배너 없음).
- **음식 목표 각도 토글(탑뷰/45°)**: 음식 모드에서 모드 토글 아래 표시. 모드·각도 전환 시 안정화기 초기화.
- **범위 밖으로 둔 것**: UNDEREXPOSED_MEAN_LUMA_MIN, SUBJECT_CENTER_TOLERANCE, FULL_BODY_HEIGHT, FOOT_MARGIN_MAX는 SPEC 규칙 목록에 대응 규칙이 없어 상수만 두고 쓰지 않는다. 사람이 없는 장면에서도 "좋아요"가 나올 수 있다(자동 촬영은 Phase 5의 눈 뜸 조건으로 막힌다).
- **알려진 한계**: 피치는 후면 카메라 기준. 전면 전환(Phase 6) 때 부호를 바꾼다.

## Phase 5 — 자동 촬영

- **판정과 상태를 분리**: CaptureReadiness가 프레임마다 "준비됨 / 무엇을 기다리는지"를 판정하고, AutoCaptureStateMachine은 그 불리언과 시간만 본다. 조건 순서: 구도(Advice.Good) → 카메라 흔들림(자이로 < 0.05) → 인물 모드만 얼굴 있음·두 눈 > 0.7·|yaw| < 15°·poseMotion < 0.01.
- **모르면 미충족**: 눈 뜸 확률 null, poseMotion null(관절 못 잡음), 얼굴 없음은 모두 "기다림"으로 처리. 시간 초과 폴백 없음. 조건이 700ms 끊김 없이 유지된 프레임에서만 촬영 신호가 나간다(타임스탬프는 분석 프레임 기준).
- **POSE_MOTION_STILL_MAX = 0.01** (100ms당 화면의 1%): SPEC에 값이 없어 새로 정함. 실기기에서 DBG의 motion 값을 보고 조정.
- **쿨다운 해제 조건**: 포즈 중심(신뢰 관절 평균)이 촬영 당시보다 0.15 이상 이동, 또는 피치 15° 이상 변화. 포즈를 놓친 프레임은 변화로 보지 않는다(검출 깜빡임으로 같은 장면을 재촬영하지 않도록). 음식 모드는 포즈가 없어 피치 변화로만 풀린다 — 같은 각도로 다른 접시를 찍으려면 AUTO를 껐다 켠다.
- **연사는 JPEG 바이트로 받는다**: 12MP Bitmap 3장(약 150MB)을 동시에 들지 않도록, 3장을 연달아 JPEG로 받고 → 긴 변 1280px 이상으로 줄여 디코딩해 채점 → 고른 1장만 원본 크기로 디코딩. 셔터음은 연사 첫 장에만.
- **베스트 컷 점수**: 0.5 × (선명도 / 연사 중 최대 선명도) + 0.5 × 눈 뜸. 선명도는 라플라시안 분산, 눈 뜸은 사진 속 모든 얼굴 중 가장 덜 뜬 눈의 확률(단체 사진 대비). 아무 사진에서도 얼굴을 못 찾았거나 음식 모드면 선명도만 본다. StillFaceDetector에 눈 분류(CLASSIFICATION_MODE_ALL)를 켰고, 채점 때 찾은 얼굴 박스를 피부 보정에 재사용한다.
- **수동/자동 촬영 경합**: isCapturing을 compareAndSet으로 잡는다. 수동 촬영 중에 자동 신호가 오면 건너뛰고 쿨다운으로 넘긴다. 촬영 실패도 쿨다운으로 넘겨 실패 루프를 막는다.
- **UI**: 프리뷰 우상단 AUTO 토글(기본 OFF, 저장 안 함). 구도가 맞은 상태에서 배너 문구가 "눈 뜨는 순간을 기다리는 중…" 등 대기 이유 → "그대로 멈춰 주세요…" → "촬영 중…" → "찍었어요! 구도를 바꾸면 다시 찍어요"로 바뀐다. 모드·음식 각도 전환, AUTO 토글 시 상태 머신 초기화.

## Phase 6 — 마무리

- **전면/후면 전환**: 하단 셔터 오른쪽에 전환 버튼(전면 카메라가 있는 기기만, 촬영 중 비활성). 설정 버튼은 화면 상단 오른쪽으로 옮김. 렌즈 상태는 ViewModel이 들고, CameraPreview가 그 값을 키로 다시 바인딩한다. 전환 시 조언 안정화기·자동 촬영 상태 머신·얼굴 박스 초기화.
- **전면 카메라 피치 부호**: 전면 카메라는 화면 쪽을 보므로 FrameAnalyzer에서 피치 부호를 뒤집는다(규칙·쿨다운이 "지금 카메라가 보는 방향" 기준이 되도록). 롤은 기기 자체의 기울기라 그대로.
- **전면 촬영본은 거울 반전하지 않는다**: 프리뷰만 거울처럼 보이고 저장본은 실제 방향(CameraX 기본). 분석 좌표·피부 보정 마스크도 반전 없는 좌표계라 그대로 맞는다.
- **권한**: 첫 실행 시 요청. 거절 후 시스템이 더 묻지 않는 상태("다시 묻지 않음")면 "앱 설정 열기" 버튼으로 안내하고, 설정에서 돌아오면(ON_RESUME) 다시 확인한다.
- **에러 처리**: 카메라 바인딩 실패 시 토스트 안내, 전면에서 실패하면 후면으로 자동 복귀. 분석 시작·밝기 분석이 예외를 던져도 프레임을 반드시 닫아 분석이 멈추지 않게 했다. 촬영·저장 실패는 기존대로 토스트.
- **성능 점검 도구**: DBG 오버레이 첫 줄에 프리뷰 fps(GL 렌더러가 실제 그린 프레임 수)와 분석 지연(ms). 분석은 별도 단일 스레드 + KEEP_ONLY_LATEST + 100ms 스로틀이라 프리뷰(GL 스레드)를 막지 않는 구조. 실기기에서 인물 모드 분석 중 프리뷰 fps가 카메라 기본(보통 30)에서 떨어지지 않는지 확인한다.
- **알려진 한계**: 회전 벡터 센서가 없는 기기는 롤·피치가 0으로 남아 수평·높이 규칙이 항상 통과한다. 자이로가 없으면 흔들림 조건이 항상 통과한다(자동 촬영은 나머지 조건으로만 판단).

## 배포·업데이트

- **배포 위치**: GitHub Releases (choimy0204/AICam). 서버 없이 공개 API로 최신 릴리스를 조회한다(인증 없이 IP당 시간당 60회, 앱 시작마다 1회라 충분).
- **버전 비교**: 릴리스 태그(`v1.1`)와 설치된 versionName을 점 단위 숫자로 비교한다(AppVersion). versionCode는 Android 설치 규칙용으로 함께 올린다.
- **확인 시점**: 앱을 새로 열 때 조용히 확인(실패·최신이면 아무것도 안 띄움), 설정 > "업데이트 확인"으로 수동 확인(결과 문구 표시).
- **설치**: Play 스토어가 아니므로 APK를 캐시에 내려받아 FileProvider로 시스템 설치 화면에 넘긴다. "출처를 알 수 없는 앱 설치" 허용이 없으면 그 설정 화면을 먼저 연다. 끝까지 받은 파일만 설치 대상이 되도록 `.part`로 받은 뒤 이름을 바꾼다.
- **서명**: 업데이트는 같은 키로 서명된 APK끼리만 되므로 배포용 키를 따로 만들고 저장소 밖에 둔다(keystore/, keystore.properties는 .gitignore). 디버그 키는 PC마다 달라서 쓰지 않는다.
- **APK 크기**: 64비트 ARM(arm64-v8a)용 네이티브 라이브러리만 넣는다. 다른 CPU용 ML Kit 라이브러리까지 넣으면 141MB였고, 휴대폰 브라우저가 다운로드 마지막의 APK 보안 검사에서 멈췄다. 빼고 나니 58MB. 32비트 폰과 x86 에뮬레이터는 지원하지 않는다.
- **프리뷰 회전**: 카메라를 SurfaceTexture에 직접 연결하면 카메라가 센서 회전·전면 거울 반전을 텍스처 변환 행렬에 이미 넣는다(TransformationInfo.hasCameraTransform). 정점 행렬에서 rotationDegrees로 또 돌리면 프리뷰가 옆으로 눕는다(v1.0.1까지의 버그). 이 경우 정점 행렬은 화면 맞춤 확대만 하고, 화면 비율 계산에는 전체 회전각을 그대로 쓴다. 화면이 세로 고정이고 폰의 기본 방향이 세로라는 전제다.

## 인물 모드: 사람이 없거나 너무 작을 때

- 기존 규칙은 모두 "사람이 있다"는 전제에서 구도만 봤다. 그래서 거울 속 작은 얼굴만 잡힌 장면에서도 지적할 게 없어 "좋아요"가 되고 자동 촬영까지 됐다.
- `SubjectPresenceRule`(우선순위 0)을 인물 규칙 맨 앞에 둔다. 관절도 얼굴도 없으면 "사람이 화면에 들어오게", 너무 작으면 "더 가까이"라고 한다.
- 크기 기준: 전신은 얼굴이 원래 작으므로 코→발목 길이(`SUBJECT_BODY_SPAN_MIN` 0.45), 그 외에는 얼굴 박스 높이(`SUBJECT_FACE_HEIGHT_MIN` 0.07). 실기기에서 조정한다.

## 인물 구도 사전조사 (v1.0.4)

웹 자료를 조사해 인물 규칙을 정리했다.
- 참고: SLR Lounge "Portrait Cropping Guide", Zoner "Foundations of Portrait Composition", Photofocus "A guide to cropping portraits", Samsung Members "갤럭시 카메라를 활용한 인물사진 촬영법", 경기도 "다리 길어 보이게 찍어줘", 삼성반도체 뉴스룸 인물 사진 노하우.

| 자료에서 공통으로 말하는 것 | 앱 반영 |
|---|---|
| 눈을 위쪽 3분할선에 둔다 (상반신·클로즈업) | `EyeLineRule`: 눈 높이가 1/3 ± 0.06을 벗어나면 위/아래로 기울이라고 안내. 이런 샷은 머리 위 여백을 따로 보지 않는다 (클로즈업은 머리 위를 잘라도 되고, 눈을 맞추면 여백도 맞음) |
| 전신은 발끝을 화면 아래에 붙이고 머리 위를 넉넉히, 카메라는 낮게 (다리가 길어 보임) | `FootMarginRule` 추가(발목 아래 여백 최대 0.12). `HeadroomRule`은 전신에서 "빠듯함"만 본다. 기존의 "여백이 넓으면 아래로" 안내는 다리를 짧아 보이게 하는 방향이고, 크기 규칙과 서로 반대로 안내하는 충돌도 있어 뺐다. 카메라 높이는 기존 `CameraHeightRule` |
| 관절(발목·무릎·엉덩이·팔꿈치·손목)에서 자르지 않는다 | `BodyCropRule`에 엉덩이 추가. 손목은 포즈 결과에 아직 넣지 않아 제외 |
| 인물을 3분할선이나 가운데에 둔다 | `SubjectPlacementRule`: 얼굴 중심이 가운데·1/3·2/3선에서 0.05 안에 없으면 안내. 우선순위가 가장 낮다. 전면 카메라는 거울상이라 좌우 방향은 말하지 않는다 |
| 시선 방향으로 여백(리드룸) | 미반영. 자동 촬영이 정면 얼굴(|yaw|<15°)을 요구하므로 시선 방향 여백이 의미 있는 경우가 적다 |
